# 카메라 검증 스파이크

**목적:** "getUserMedia로 찍으면 휴대폰에 파일이 남지 않는다"는 설계 최대 가정을
아이폰·안드로이드 실기에서 확인한다. 이 검증을 통과해야 본 개발에 들어간다.

빌드 없음. 서버 코드 없음. `index.html` 하나로 끝.

---

## 실행

로컬 서버는 이미 준비돼 있습니다.

```bash
python -m http.server 8080 --directory spike/camera
```

**폰에서 열려면 HTTPS가 필요합니다.** 카메라 API는 보안 컨텍스트에서만 동작하고,
`http://192.168.x.x` 같은 LAN 주소는 보안 컨텍스트가 아닙니다.

### 방법 1 — 사무실 서버로 접속 (권장)

**[docs/SETUP.md](../../docs/SETUP.md) 를 마쳤다면 추가 작업이 전혀 없습니다.**
수신 서버가 이 페이지를 함께 서빙하므로, 폰에서 사무실 주소로 접속하면 바로 뜹니다.
어차피 해야 할 설치이고, 실제 운영 환경에서 검증하는 셈이라 가장 정확합니다.

### 방법 2 — 안드로이드 전용, 설치 없음

USB 연결 → PC 크롬에서 `chrome://inspect` → Port forwarding → `8080 → localhost:8080`.
폰 크롬에서 `http://localhost:8080` 접속. localhost는 보안 컨텍스트로 취급됩니다.

## 테스트 절차

기기마다 아래를 그대로 반복합니다. **아이폰 1대 + 갤럭시 1대가 최소**이고,
현장에서 실제로 쓰는 기종이 따로 있으면 그 기종을 반드시 포함시킵니다.

1. 페이지 접속 → **환경 진단**에서 `보안 컨텍스트`, `getUserMedia 지원`이 모두 "예"인지 확인
2. **방식 A**: 카메라 켜기 → 촬영 3장
3. 앱을 벗어나 **사진앱 / 갤러리를 직접 열어** 확인 → 결과를 페이지에 기록
4. **방식 B**: OS 카메라로 촬영 1장
5. 다시 **갤러리 확인** → 결과 기록
6. **E2E 암호화 자가진단** → "300KB 사진으로 왕복 시험" 1회 실행
7. **결과 리포트** 전체 복사해서 전달

### 홈화면 추가 상태로 한 번 더

실제 사용 형태가 그것이므로 반드시 재확인합니다.
iOS: 공유 → 홈 화면에 추가 / Android: 메뉴 → 앱 설치.
설치본으로 열어 2~5를 반복 (진단의 `홈화면 실행`이 "예"로 바뀌어야 함).

## 판정 기준

| 결과 | 의미 |
|---|---|
| A=없음 | ✅ 설계 유효. 본 개발 진행 |
| A=없음, B=있음 | ✅ 최상. `<input capture>` 금지 근거까지 실기로 확보 |
| **A=있음** | 🚨 **중대**. 해당 기종에서 설계 전제가 깨짐 → 원인 분석 후 재설계 |

추가로 확인할 것:

- `EXIF 포함` — 방식 A는 항상 `아니오`여야 합니다(canvas 재인코딩으로 GPS·기기정보 소멸).
  방식 B는 대개 `예`로 나옵니다. 개인정보 관점에서 A의 또 다른 이점입니다.
- `용량` — 1600px / q=0.8 기준 200~400KB가 정상 범위. 현장 회선에서 감당 가능한지 판단.
- `캡처 소요` — 100ms를 크게 넘으면 구형 기기 UX 검토 필요.
- 연속 촬영 5장 후 앱이 죽지 않는지 (iOS Safari 메모리 압박 확인).

암호화 자가진단은 아래를 확인합니다 (데스크톱 실측: 암호화 1ms, 전송량 증가 93B).

- `왕복 일치` / `변조 시 거부` / `id 위조 시 거부` 가 모두 **예**여야 합니다.
- `암호화 소요`가 구형 폰에서 200ms를 넘으면 촬영 UX에 체감되므로 화질 조정을 검토합니다.
- 실패하면 해당 기종에서 P-256 ECDH 또는 HKDF 미지원이라는 뜻입니다(가능성 낮음).
